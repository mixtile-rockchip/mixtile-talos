## Summary

Talos Linux v1.14.4 (kernel 6.18.57-talos) for the **Mixtile Blade 3**
(RK3588) with **openmiop** built in: Ethernet (`omi0`) between the blades of
a Mixtile Cluster Box over its PCIe switch. Nothing has to be compiled.

**v0.6.1** is the Blade OS of OpenMIOP Stack v0.6.1. The openmiop driver,
DTB and U-Boot are the same as in v0.6.0; what changes:

* **Talos v1.14.4** (from v1.14.2): Linux 6.18.57, and the drbd 9.3.4,
  zfs 2.4.4, iscsi-tools, panfrost and rockchip-rknn extensions released
  for it.
* **One source release for all blade modules:** openmiop-ep and the Blade 3
  board modules (`blade3-leds`, `blade3-nvme-recover`) are built from
  [pcie-ep-net v0.6.1](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.6.1),
  the way Talos builds out-of-tree modules (`modules_install` into
  `extras`, stripped, signed at build time). This is the groundwork for
  an official image ([docs/upstream.md](https://github.com/roysbike/mixtile-talos/blob/v0.6.1/docs/upstream.md)).
* `console=ttyFIQ0` is gone from the kernel arguments (it only exists on
  vendor kernels); the serial console stays `ttyS2` at 1500000 baud.

Built by [GitHub Actions](@RUN_URL@) from commit `@COMMIT@`.
Changes: [CHANGELOG.md](https://github.com/roysbike/mixtile-talos/blob/v0.6.1/CHANGELOG.md).

| --- | --- |
| **Upgrade** an existing Talos node | installer image `@INSTALLER@` (nothing to download) |
| **Install** a new Blade 3 (eMMC / microSD) | `@IMAGE@` |

| Verify | `SHA256SUMS`, `BUILD-INFO.txt` |

Inside the image: Talos v1.14.4, kernel 6.18.57-talos, the v0.3.0 DTB and
U-Boot 2026.07, and the extensions openmiop 0.6.1 (pcie-ep-net
`@OPENMIOP_REF@`: `openmiop-ep`, `blade3-nvme-recover`, `blade3-leds`),
drbd, zfs, iscsi-tools, panfrost, rockchip-rknn. `module.sig_enforce` is
off: the modules are signed with the throw-away key of this build, not
with the Talos key. Image references: extension `@EXTENSION@`, overlay
`@OVERLAY@`. Kubernetes is not pinned by the image (tested with v1.34.3).

## Supported hardware

Mixtile Blade 3 (RK3588), standalone or in a Mixtile Cluster Box.
Gateway pull and zero-copy need the BMC's `omi-rc` from pcie-ep-net
v0.5.0 or later:
[ClusterBox firmware v0.4.0](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.4.0)
(or v0.3.0).

## Install a new node

As in [v0.3.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.3.0#install-a-new-node),
with this release's image and `machine.install.image: @INSTALLER@`. The
serial console must show `enabling system extension openmiop 0.6.1-v1.14.4`.

## Upgrade an existing node

One node at a time; mind etcd quorum; wait until DRBD and the databases
are healthy again before the next node.

```sh
talosctl -n <node> upgrade --image @INSTALLER@
```

* Keep the default drain (no `--drain=false`).
* Always pass `--image` and keep `machine.install.image` in the machine
  configuration equal to it; do not set
  `machine.install.grubUseUKICmdline: false`.
* Cordon a node that holds a CNPG primary first and wait for the
  switchover; move WAL-archiving primaries off a node with a local
  SeaweedFS volume server before draining it.
* Same machine configuration as v0.6.0. Rollback:
  `talosctl -n <node> rollback`.

## Verification

```sh
talosctl -n <node> version                     # Tag: v1.14.4
talosctl -n <node> get extensions              # openmiop 0.6.1-v1.14.4
talosctl -n <node> dmesg | grep openmiop       # "peer N up, ..., checksum offload"
talosctl -n <node> get kernelmodulestatus | grep blade3   # blade3_leds, blade3_nvme_recover
```

The kernel log still shows `module verification failed: signature and/or
required key missing - tainting kernel` once: the modules are not signed
with the Talos key.

## Tested

Lab Cluster Box, BMC on firmware v0.4.0: the pull-request build of this
release (same sources, installer `sha256:24a6f518…`) rolled with drain on
all four blades, .108 on 2026-10-20 and .204, .133, .201 on 2026-10-21,
CNPG primaries moved off by cordon first. On every node openmiop 0.6.1
loaded, all peers up with checksum offload, NVMe Gen3 x2;
`scripts/openmiop-verify.sh` passed on .108. Afterwards etcd 3/3, CNPG
healthy, ZFS clean, DRBD in sync. This release build is inspected in CI
(`scripts/verify-installer.sh`).

## Known limitations

* The BMC CPU is still the gateway limit (~200-280 Mbit/s to a blade).
* A BMC reboot drops every blade link for the length of its boot; with
  DRBD 9.3.4 check `out-of-sync:` 0 before
  ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)).
* One TCP flow uses one queue (7.8-8.0 Gbit/s); four flows reach
  ~11 Gbit/s between two blades. No TSO/GSO.
* `module.sig_enforce` stays off until the module is built and signed in
  siderolabs/pkgs.
