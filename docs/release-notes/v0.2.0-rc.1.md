## Summary

Talos Linux v1.14.2 (kernel 6.18.54-talos) for the **Mixtile Blade 3**
(RK3588) with **openmiop** built in: Ethernet (`omi0`) between the blades of
a Mixtile Cluster Box over its PCIe switch. Nothing has to be compiled.

**v0.2.0-rc.1:** openmiop 0.2.0-rc.1 — RX and TX interrupts instead of
polling threads and 4 queue pairs (RSS) over both eDMA channels: ~8 Gbit/s
between two blades with several flows, 22 Gbit/s for four blades sending at
once (rc.2: 11.7), `omi-ctl` ~1 % of a core (was ~6 %). Works with rc.2
blades. Kernel, DTB, U-Boot and the other extensions are unchanged.

Built by [GitHub Actions](@RUN_URL@) from commit `@COMMIT@`.
Changes: [CHANGELOG.md](https://github.com/roysbike/mixtile-talos/blob/v0.2.0-rc.1/CHANGELOG.md).

## What to download

| You want to | Use |
| --- | --- |
| **Upgrade** an existing Talos node | installer image `@INSTALLER@` (nothing to download) |
| **Install** a new Blade 3 (eMMC / microSD) | `@IMAGE@` |
| Flash U-Boot / DTB by hand, inspect the module | `@BOOTFILES@` (DTB, `u-boot-rockchip.bin`, `openmiop-ep.ko`, extension manifest) |
| Verify | `SHA256SUMS`, `BUILD-INFO.txt` |

Inside the image: Talos v1.14.2, kernel 6.18.54-talos, DTB with the Cluster
Box PCIe endpoint (`fe150000`), NVMe on `fe160000` at Gen3 x2 and the PCIe
SMMU off, U-Boot 2026.07, and the extensions openmiop 0.2.0-rc.1
(pcie-ep-net `@OPENMIOP_REF@`), drbd, zfs, iscsi-tools, panfrost,
rockchip-rknn. `module.sig_enforce` is off (the openmiop module is unsigned).
Image references: extension `@EXTENSION@`, overlay `@OVERLAY@`.
Kubernetes is not pinned by the image (tested with v1.34.3).

## Supported hardware

Mixtile Blade 3 (RK3588), standalone or in a Mixtile Cluster Box. The
Cluster Box BMC must run the openmiop helper:
[ClusterBox firmware v0.1.0-rc.3](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.0-rc.3)
(rc.1 and rc.2 work too; the BMC side did not change for v0.2).

## Install a new node

```sh
sha256sum -c --ignore-missing SHA256SUMS
xz -d @IMAGE@
# microSD (destroys the disk):  sudo dd if=<image>.raw of=/dev/<disk> bs=4M conv=fsync
# eMMC over USB (Maskrom):       see the README (scripts/flash-blade3-macos.sh)
```

The serial console must show
`enabling system extension openmiop 0.2.0-rc.1-v1.14.2`. In maintenance mode
apply your machine configuration with the openmiop documents below,
`machine.install.disk: /dev/mmcblk0` and
`machine.install.image: @INSTALLER@`.

```yaml
machine:
  kernel:
    modules:
      - name: openmiop_ep
---
apiVersion: v1alpha1
kind: LinkAliasConfig
name: omi0
selector:
  match: link.driver == "openmiop-ep"
---
apiVersion: v1alpha1
kind: LinkConfig
name: omi0
up: true
mtu: 9000
addresses:
  - address: 10.20.0.<last octet of the management address>/24
```

Notes from the lab:
* A configuration applied to a node that booted an **older** raw image does
  not reinstall it; run `talosctl upgrade --image @INSTALLER@` on it.
* A new control-plane node cannot join etcd while the cluster lists a dead
  member (`etcdserver: unhealthy cluster`); remove that member first
  (`talosctl etcd snapshot`, then `talosctl etcd remove-member <id>`).

## Upgrade an existing node

One node at a time; mind etcd quorum.

```sh
talosctl -n <node> upgrade --image @INSTALLER@ --stage --drain=false
```

`--stage` installs on the next boot, before volumes are mounted, so the
reboot cannot hang in pod unmounts; `--drain=false` because the
client-side drain never finishes on nodes with CNPG primaries (their PDBs
allow no eviction); Talos stops the pods itself. Uncordon afterwards if a
drain had started. From rc.1/rc.2 nothing else changes (same machine
configuration). Mixed rc.2/v0.2 nodes work during the rollout. Rollback:
`talosctl -n <node> rollback`.

## Verification

```sh
talosctl -n <node> read /proc/cmdline          # no module.sig_enforce
talosctl -n <node> get extensions              # openmiop 0.2.0-rc.1-v1.14.2
talosctl -n <node> dmesg | grep openmiop       # "RX doorbell: 15 buses x 4 queues", "peer M up, 4 queues, doorbell"
talosctl -n <node> get links | grep omi0       # alias omi0 on enx<mac>, up
talosctl -n <node> get addresses | grep 10.20.0
```

## Tested

Cluster Box with four Blade 3 (three control planes, one worker), BMC on
ClusterBox firmware rc.3. Development builds of this repository with the
same kernel, DTB, extensions and openmiop driver source as this release
were installed with staged upgrades on all four nodes, one at a time;
every peer pair came up with 4 queues and doorbells. Every ordered pair
with 4 TCP flows: 7.9-8.4 Gbit/s; four blades sending at once: 22.2
Gbit/s; one flow: 4.1-4.8 Gbit/s; no driver errors. A BMC reboot and hard
resets of all four blades afterwards: all peers reconnected. This release
build is inspected in CI (`scripts/verify-installer.sh`).

## Known limitations

* One TCP flow uses one queue and one eDMA channel (~4.7 Gbit/s).
* A BMC reboot (e.g. a firmware update) takes the fabric down for minutes;
  on the lab cluster DRBD 9.3.4 deadlocked afterwards (`__drbd_md_sync`)
  and every node needed a reboot (most hung in pod unmounts and needed a
  hard reset of their slot). Plan BMC updates as maintenance.
* A blade that disappears without the leave handshake can race a BMC read
  and wedge the fabric until the BMC reboots.
* Not hardware-tested: NPU/GPU workloads (drivers load), VFIO, more than
  four blades.
