## Summary

Talos Linux v1.14.2 (kernel 6.18.54-talos) for the **Mixtile Blade 3**
(RK3588) with **openmiop** built in: Ethernet (`omi0`) between the blades of
a Mixtile Cluster Box over its PCIe switch. Nothing has to be compiled.

**v0.6.0** is the Blade OS of OpenMIOP Stack v0.6.0. Kernel, DTB, U-Boot
and the other extensions are the same as in v0.5.0; only openmiop
changes:

* **Blade to blade: one TCP flow 7.8-8.0 Gbit/s (5.0-5.5 in v0.5.0).**
  The TX threads and eDMA interrupts run on the Cortex-A76 cores, and
  TCP/UDP checksums are left to the receiving blade (checksum offload,
  as on virtio-net; the payload only crosses PCIe links with LCRC).
  Negotiated per pair: v0.6 and older blades work together during a
  rolling upgrade, a pair gets the offload when both run v0.6.
* Frames to the BMC gateway are unchanged (full checksum); the BMC needs
  no update.

Built by [GitHub Actions](@RUN_URL@) from commit `@COMMIT@`.
Changes: [CHANGELOG.md](https://github.com/roysbike/mixtile-talos/blob/v0.6.0/CHANGELOG.md).

Inside the image: Talos v1.14.2, kernel 6.18.54-talos, the v0.3.0 DTB and
U-Boot 2026.07, and the extensions openmiop 0.6.0 (pcie-ep-net
`@OPENMIOP_REF@`; also `blade3-nvme-recover` and `blade3-leds`), drbd,

(the openmiop module is unsigned). Image references: extension
`@EXTENSION@`, overlay `@OVERLAY@`. Kubernetes is not pinned by the image
(tested with v1.34.3).

## Supported hardware

Mixtile Blade 3 (RK3588), standalone or in a Mixtile Cluster Box.
Gateway pull and zero-copy need the BMC's `omi-rc` from pcie-ep-net
v0.5.0 or later:
[ClusterBox firmware v0.3.0](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.3.0).

## Install a new node

As in [v0.3.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.3.0#install-a-new-node),
with this release's image and `machine.install.image: @INSTALLER@`. The
serial console must show `enabling system extension openmiop 0.6.0-v1.14.2`.

## Upgrade an existing node

One node at a time; mind etcd quorum; wait until DRBD and the databases
are healthy again before the next node.

```sh
talosctl -n <node> upgrade --image @INSTALLER@
```

* Keep the default drain (no `--drain=false`).
* Always pass `--image` and keep `machine.install.image` in the machine
  configuration equal to it; do not set
  `machine.install.grubUseUKICmdline: false`.
* After each drain check that no CNPG replica landed on the node of its
  primary, and move WAL-archiving primaries off a node with a local
  SeaweedFS volume server before draining it.
* Same machine configuration as v0.5.0. Rollback:
  `talosctl -n <node> rollback`.

## Verification

```sh
talosctl -n <node> get extensions              # openmiop 0.6.0-v1.14.2
talosctl -n <node> dmesg | grep openmiop       # "TX threads and eDMA interrupts on CPUs 4-7"
                                               # "peer N up, ..., checksum offload" (peer on v0.6)
```

## Tested

Lab Cluster Box, 2026-10-19/20: the same driver without the final
tx_build hardening (test image ci-61, openmiop 0.5.3-dev.1) on .108 and
.201, v0.5.0 with TX pinned to the A76 by hand on .133 and .204, BMC on
the OpenWrt 25.12 development firmware. This release build is inspected
in CI (`scripts/verify-installer.sh`).

| Test | v0.5.0 | v0.6.0 pair |
| --- | --- | --- |
| One TCP flow blade to blade | 5.0-5.5 Gbit/s | 7.82-7.98 Gbit/s |
| Four TCP flows | 10.0-10.5 Gbit/s (pinned by hand) | 11.1-11.3 Gbit/s |

Integrity (hashes on both ends): TCP over IPv4/IPv6, UDP datagrams,
pod to pod and ClusterIP over Kube-OVN Geneve, and downloads through the
BMC gateway via a NodePort on another blade: all identical,
`InCsumErrors` 0. One hour soak with load and 1 GiB integrity loops:
1 232 transfers identical, no driver messages, DRBD clean. Upgrade with
drain, DRBD resync and CNPG switchover were fine.

## Known limitations

* The BMC CPU is still the gateway limit (~200-280 Mbit/s to a blade).
* A BMC reboot drops every blade link for the length of its boot; with
  DRBD 9.3.4 check `out-of-sync:` 0 before
  ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)).
* One TCP flow uses one queue; four flows reach ~11 Gbit/s between two
  blades. No TSO/GSO.
