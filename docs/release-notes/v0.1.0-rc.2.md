## Summary

Talos Linux v1.14.2 (kernel 6.18.54-talos) for the **Mixtile Blade 3**
(RK3588) with **openmiop** built in: Ethernet (`omi0`) between the blades of
a Mixtile Cluster Box over its PCIe switch. Nothing has to be compiled.

**rc.2:** openmiop 0.1.0-rc.2 — peers no longer stay "connecting" after the
BMC re-enumerates the fabric and blade BAR addresses move (blades removed or
added). Kernel, DTB, U-Boot and the other extensions are unchanged. Release
assets renamed to one scheme.

Built by [GitHub Actions](@RUN_URL@) from commit `@COMMIT@`.
Changes: [CHANGELOG.md](https://github.com/roysbike/mixtile-talos/blob/v0.1.0-rc.2/CHANGELOG.md).

## What to download

| You want to | Use |
| --- | --- |
| **Upgrade** an existing Talos node | installer image `@INSTALLER@` (nothing to download) |
| **Install** a new Blade 3 (eMMC / microSD) | `@IMAGE@` |
| Flash U-Boot / DTB by hand, inspect the module | `@BOOTFILES@` (DTB, `u-boot-rockchip.bin`, `openmiop-ep.ko`, extension manifest) |
| Verify | `SHA256SUMS`, `BUILD-INFO.txt` |

Inside the image: Talos v1.14.2, kernel 6.18.54-talos, DTB with the Cluster
Box PCIe endpoint (`fe150000`), NVMe on `fe160000` at Gen3 x2 and the PCIe
SMMU off, U-Boot 2026.07, and the extensions openmiop 0.1.0-rc.2
(pcie-ep-net `@OPENMIOP_REF@`), drbd, zfs, iscsi-tools, panfrost,
rockchip-rknn. `module.sig_enforce` is off (the openmiop module is unsigned).
Image references: extension `@EXTENSION@`, overlay `@OVERLAY@`.
Kubernetes is not pinned by the image (tested with v1.34.3).

## Supported hardware

Mixtile Blade 3 (RK3588), standalone or in a Mixtile Cluster Box. The
Cluster Box BMC must run the openmiop helper:
[ClusterBox firmware v0.1.0-rc.1](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.0-rc.1)
(unchanged in rc.2).

## Install a new node

```sh
sha256sum -c --ignore-missing SHA256SUMS
xz -d @IMAGE@
# microSD (destroys the disk):  sudo dd if=<image>.raw of=/dev/<disk> bs=4M conv=fsync
# eMMC over USB (Maskrom):       see the README (scripts/flash-blade3-macos.sh)
```

The serial console must show
`enabling system extension openmiop 0.1.0-rc.2-v1.14.2`. In maintenance mode
apply your machine configuration with the openmiop documents below,
`machine.install.disk: /dev/mmcblk0` and
`machine.install.image: @INSTALLER@`.

```yaml
machine:
  kernel:
    modules:
      - name: openmiop_ep
---
apiVersion: v1alpha1
kind: LinkAliasConfig
name: omi0
selector:
  match: link.driver == "openmiop-ep"
---
apiVersion: v1alpha1
kind: LinkConfig
name: omi0
up: true
mtu: 9000
addresses:
  - address: 10.20.0.<last octet of the management address>/24
```

Notes from the lab:
* A configuration applied to a node that booted an **older** raw image does
  not reinstall it; run `talosctl upgrade --image @INSTALLER@` on it.
* A new control-plane node cannot join etcd while the cluster lists a dead
  member (`etcdserver: unhealthy cluster`); remove that member first
  (`talosctl etcd snapshot`, then `talosctl etcd remove-member <id>`).

## Upgrade an existing node

One node at a time; mind etcd quorum.

```sh
talosctl -n <node> upgrade --image @INSTALLER@
```

From rc.1 nothing else changes (same machine configuration). If the drain
cannot finish (pods on failed storage), add `--drain=false` and uncordon
afterwards. Rollback: `talosctl -n <node> rollback`.

## Verification

```sh
talosctl -n <node> read /proc/cmdline          # no module.sig_enforce
talosctl -n <node> get extensions              # openmiop 0.1.0-rc.2-v1.14.2
talosctl -n <node> dmesg | grep openmiop       # node N, peer M up
talosctl -n <node> get links | grep omi0       # alias omi0 on enx<mac>, up
talosctl -n <node> get addresses | grep 10.20.0
```

## Tested

Cluster Box with four Blade 3 (three control planes, one worker) and the
BMC on ClusterBox firmware rc.1. The rc.2 test build of this repository
(same kernel, DTB `af047eb2…`, extensions and openmiop driver source as
this release) was installed with `talosctl upgrade` on all four nodes,
one at a time: each came back with openmiop 0.1.0-rc.2, all three peers
up and etcd at full membership. Then BAR addresses were moved on purpose
twice (graceful shutdown of one blade with a BMC re-enumeration, and its
return): all 12 peer directions reconnected by themselves. Jumbo ping
(8972 bytes) from the BMC to all four blades. This release build is
inspected in CI (`scripts/verify-installer.sh`).

## Known limitations

* openmiop RX is polled; interrupt-driven RX is not implemented or tested. No multiqueue.
* Talos receives ~20 % slower than Debian (not investigated).
* A BMC re-enumeration pauses fabric traffic ~1-2 s when a blade appears
  without a BAR address; a blade that disappears without the leave
  handshake can race a BMC read and wedge the fabric until the BMC reboots.
* Not hardware-tested: NPU/GPU workloads (drivers load), VFIO, more than
  four blades.
