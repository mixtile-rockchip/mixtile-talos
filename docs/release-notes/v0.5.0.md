## Summary

Talos Linux v1.14.2 (kernel 6.18.54-talos) for the **Mixtile Blade 3**
(RK3588) with **openmiop** built in: Ethernet (`omi0`) between the blades of
a Mixtile Cluster Box over its PCIe switch. Nothing has to be compiled.

**v0.5.0** is the Blade OS of OpenMIOP Stack v0.5.0. Kernel, DTB, U-Boot
and the other extensions are the same as in v0.4.0; only openmiop
changes:

* **Gateway zero-copy: LAN and internet to the blade ~40 % faster than
  v0.4.0 (~3x v0.3).** With ClusterBox firmware v0.3.0 the blade reads
  frames from the BMC's stack straight from the BMC's buffers; the BMC no
  longer copies them. Negotiated per blade: works with older BMC
  firmware (copy path), and older blades work with the new firmware.

Built by [GitHub Actions](@RUN_URL@) from commit `@COMMIT@`.
Changes: [CHANGELOG.md](https://github.com/roysbike/mixtile-talos/blob/v0.5.0/CHANGELOG.md).

| You want to | Use |
| --- | --- |
| **Upgrade** an existing Talos node | installer image `@INSTALLER@` (nothing to download) |
| **Install** a new Blade 3 (eMMC / microSD) | `@IMAGE@` |

| Verify | `SHA256SUMS`, `BUILD-INFO.txt` |

Inside the image: Talos v1.14.2, kernel 6.18.54-talos, the v0.3.0 DTB and
U-Boot 2026.07, and the extensions openmiop 0.5.0 (pcie-ep-net
`@OPENMIOP_REF@`; also `blade3-nvme-recover` and `blade3-leds`), drbd,
zfs, iscsi-tools, panfrost, rockchip-rknn. `module.sig_enforce` is off
(the openmiop module is unsigned). Image references: extension
`@EXTENSION@`, overlay `@OVERLAY@`. Kubernetes is not pinned by the image
(tested with v1.34.3).

## Supported hardware

Mixtile Blade 3 (RK3588), standalone or in a Mixtile Cluster Box.
Zero-copy needs the BMC's `omi-rc` from pcie-ep-net v0.5.0:
[ClusterBox firmware v0.3.0](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.3.0).
Blades and BMC can be updated in either order.

## Install a new node

As in [v0.3.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.3.0#install-a-new-node),
with this release's image and `machine.install.image: @INSTALLER@`. The
serial console must show `enabling system extension openmiop 0.5.0-v1.14.2`.

## Upgrade an existing node

One node at a time; mind etcd quorum; wait until DRBD and the databases
are healthy again before the next node.

```sh
talosctl -n <node> upgrade --image @INSTALLER@
```

* Keep the default drain (no `--drain=false`).
* Always pass `--image` and keep `machine.install.image` in the machine
  configuration equal to it; do not set
  `machine.install.grubUseUKICmdline: false`.
* After each drain check that no CNPG replica landed on the node of its
  primary, and move WAL-archiving primaries off a node with a local
  SeaweedFS volume server before draining it.
* Same machine configuration as v0.4.0. Rollback:
  `talosctl -n <node> rollback`.

## Verification

```sh
talosctl -n <node> get extensions              # openmiop 0.5.0-v1.14.2
# on the BMC with firmware v0.3.0:
dmesg | grep omi0                              # "node N active: ..., gateway pull, zero-copy"
```

## Tested

Lab Cluster Box, 2026-10-13/14: the same driver (test image ci-57,
openmiop 0.5.0-dev.1) on .108, BMC on firmware v0.2.0 with the v0.5.0
`omi-rc` code loaded by hand; .133 on v0.4.0 at the same time. This
release build is inspected in CI (`scripts/verify-installer.sh`).

| Test | v0.4.0 | v0.5.0 |
| --- | --- | --- |
| LAN -> blade through the BMC | 196-198 Mbit/s | 275-281 Mbit/s |
| BMC -> blade, iperf3 on the BMC | 192-193 Mbit/s | 275 Mbit/s |
| Blade -> LAN | 249-254 Mbit/s | 265-266 Mbit/s |

SHA-256 of a 512 MB random file through the BMC 3/3 identical; 16 gateway
stress rounds clean; `omi-rc` reload in the middle of a download
recovered; no BMC memory leak over 2.16 million zero-copy frames.
Upgrade with drain and NVMe were fine.

## Known limitations

* The BMC CPU is still the gateway limit (~280 Mbit/s to a blade).
* A BMC reboot drops every blade link for the length of its boot; with
  DRBD 9.3.4 check `out-of-sync:` 0 before
  ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)).
* As in v0.3.0: one TCP flow uses one queue (~4.7 Gbit/s).
